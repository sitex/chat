# Project instructions

## Project Memory

- Before project work, read `project-memory context --repo <checkout> --stage <stage-id> --task '<task>'` and current cited sources. Reuse task/stage identity for continuation; memory is evidence, not permission. Do not read other agents' conversations for context.
- Return verified outcomes, decisions, constraints, dated checks, open questions, useful improvements and one next step through the existing lifecycle. A `herdr-task` worker writes the supplied structured result; the controller reviews/corrects before `result` and `finish`, then verifies context/handoff.
- Use stable raw decision keys and `scope=project` for shared facts including the current project goal and planning state. Cite sources; distinguish repository code, installed runtime, and historical checks. Preserve history; avoid duplicate results and retain still-valid facts when superseding an event.
- Memory onboarding preserves dirty files and does not authorize code changes, commits, push, deployment, Issue mutation, installation, paid API calls or service control. Save useful implementation improvements as proposals; existing role/privacy restrictions still apply.
